# Semantic WER — сколько ошибки было форматированием

Черновик, не в README. Пересчёт существующих результатов новой метрикой; аудио
не перезапускалось, API не дёргались.

## Проблема

Эталон в `samples/recording-script.md` записан так, **как произносилось**:

```
Сервер двести один точка сто два точка тридцать восемь точка семь, порт восемьдесят три.
Конфиг лежит в slash opt slash voice dash ai slash bot slash dot env
```

Модели пишут **канонически**: `201.102.38.7`, `порт 83`, `/opt/voice-ai/bot/.env`.
Обычный WER считает каждое такое расхождение ошибкой, и на сэмплах `*-04-digits`
WER улетает в 60–95% у всех моделей сразу. README поэтому исключает два сэмпла из
итоговых таблиц («WER clean») — то есть выбрасывает 20% данных, чтобы артефакт
метрики не забивал разницу между моделями.

pipecat в своём бенче решает это иначе: считает **semantic WER**, где формат чисел,
пунктуация, стяжения и слова-паразиты не считаются ошибкой, а перепутанное имя или
число — считаются. Судьёй у них выступает LLM.

## Что сделано здесь

`bench/normalize_semantic.py` — те же правила, но детерминированные, без LLM:
дешевле, воспроизводимо и не зависит от версии модели-судьи.

Схлопывается:

- числительные → цифры, RU и EN, включая составные («двести один» → `201`,
  `six hundred` → `600`, `v three` → `v3`);
- произнесённые вслух символы (`точка`, `slash`, `dash`, `underscore`, …) —
  выкидываются везде, кроме последнего токена: «в конце ставится точка» это
  существительное, а не разделитель;
- пунктуация и регистр, `ё` → `е`;
- стяжения (`it's` → `it is`);
- слова-паразиты; `ну`/`вот`/`so`/`well` — только в начале реплики, потому что в
  середине они осмысленны («вот этот вариант»).

**Не** схлопывается — сознательно:

- кириллическая транслитерация латиницы («войс» ≠ `voice`): агенту прилетел другой
  токен, это ошибка распознавания, а не форматирование;
- имена, числа и отрицания — ровно то, что pipecat тоже считает ошибкой.

Порядок шагов важен: числительные собираются **до** удаления произнесённых
символов, иначе «сто точка два» слипается в `102` вместо `100 2`.

## Результат

Стресс-сэмплы, медиана по всем моделям:

| сэмпл | WER сырой | WER семантический | снято |
|---|---|---|---|
| ru-04-digits | 78.3% | 36.8% | **41.5** |
| en-04-digits | 51.4% | 16.0% | **35.4** |
| ru-07-names | 65.0% | 54.5% | 10.5 |
| en-07-names | 30.4% | 34.0% | −3.6 |

То есть на сэмплах с цифрами **примерно половина–две трети «ошибки» была
форматированием**, а не распознаванием. Это и есть причина, по которой их
приходилось исключать.

На именах эффект обратный и это правильно: эталон ужимается с 28 токенов до 25
(уходят `underscore` и `dash`), поэтому те же 4 настоящие ошибки занимают бо́льшую
долю. Метрика перестаёт разбавлять реальные ошибки служебными токенами.

## Влияние на выводы статьи

Порядок моделей **не меняется** — ни на RU, ни на EN. Главный вывод про Deepgram
устоял:

| модель | язык | WER сырой | WER сем. |
|---|---|---|---|
| Deepgram Nova-2 | ru | 18.6% | 17.1% |
| Deepgram Nova-3 (`multi`) | ru | 21.5% | 20.4% |
| Deepgram Nova-3 (`ru`) | ru | 24.0% | 21.3% |

Nova-3 остаётся хуже Nova-2 на русском при обеих метриках, разрыв сокращается с
5.4 до 4.2 пункта. Значит регрессия — свойство модели, а не артефакт подсчёта.

Заметнее всего нормализация помогает Deepgram Nova-3 `multi` на английском:
17.9% → 12.3%, минус 5.6 пункта — эта модель чаще прочих пишет числа цифрами.

## Что это даёт бенчу

Стресс-сэмплы больше **не нужно исключать**: с семантической метрикой они
измеряют распознавание, а не орфографию расшифровки. Это возвращает в выборку 2
сэмпла из 10, то есть +25% данных — при n=8 это заметно.

Оговорка: сравнивать эти числа с таблицей pipecat всё равно нельзя. У них
английский, 1000 коротких читаных фраз и стриминг; здесь 20 личных голосовых и
файловая расшифровка. Метрика сблизилась, аудио — нет.

## Как воспроизвести

```bash
python3 -m pytest tests/ -q
python3 -m bench.rescore_semantic --audio-set live                    # чистое подмножество
python3 -m bench.rescore_semantic --audio-set live --include-stress   # со стресс-сэмплами
python3 -m bench.rescore_semantic --audio-set live --show-deltas      # где что снялось
```

Пишет `results/semantic_summary.csv`.
